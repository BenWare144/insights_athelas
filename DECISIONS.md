# DECISIONS.md — decisions, DOM facts, and solved problems

Why the code is the way it is, and problems already solved. Read this before "fixing" something that looks odd — it's probably deliberate. Companion to `AGENTS.md`.

## Design decisions

- **Identity:** this is a *workflow-automation helper* (one-click fixers primary). Do NOT call it "compact mode" — that framing repeatedly leaked into user-facing text and was explicitly banned. Compact CSS is a minor background feature.
- **Compact CSS is spacing-only.** (15.25.3.) The compact stylesheets may set padding, margin, gap, line-height, min-height and heading font-size, and nothing else: no width, offset, position, overflow or display, no value above 16px, and no selector on the app shell (sidebar, page container, main). The reason is how each kind of rule fails when the site changes. A spacing rule whose selector stops matching does nothing. A geometry rule keeps applying to whatever still matches: `aside.q-drawer { width: 200px }` and `.q-page-container { padding-left: 200px }` were written as a pair, the site replaced the drawer, the first matched nothing and the second pushed every note 200px right. `tests/compact-css.test.js` enforces all of this and fails on the pre-fix stylesheet. Do not "reclaim" sidebar width again — the new sidebar is user-resizable and collapsible natively.
- **Compact CSS checks itself at runtime** (`compactSelfCheck`, 15.25.3). The test only stops *us* writing a bad rule; it cannot foresee a site update changing what an existing rule does. So once per page load, after `[data-section]` appears, the script measures the horizontal span of all visible `[data-section]` blocks with its stylesheet enabled and disabled. Compaction may only widen the note; if it shifts the span right or narrows it by more than 24px, the stylesheet is removed until reload (`applyCompactCss._tripped`), with a console warning and one toast. Toggle through `style.sheet.disabled`, which is synchronous — nothing paints in between. (A `<link>`'s own `.disabled` re-fetches asynchronously; that bit the test harness, not the product, since ours is a `<style>`.) It is one forced layout pair per page load, not a timer. It only sees horizontal breakage. `window.__athelasCompactCheck()` returns the numbers.
- **Dual artifact, MAIN world:** userscript is the source of truth; `content.js` is generated from it. The extension runs in the MAIN world (needed for React `__reactFiber$` access). Because MAIN world can't reach `chrome.*`, all persistence uses page `localStorage`.
- **Matching engine three-way sync:** canonical `matching/procedure-matching.js` → userscript `Proc` → `content.js`. First matching rule wins, and the winning rule supplies BOTH the CPT code and the justification (never split).
- **The matcher takes TWO inputs now: `resolveProcedure(name, details)`.** Almost every rule keys on the NAME and ignores `details`; the simulated-activity rule (index 0) is the only one that reads it, because "simulates/replicates a functional activity" is something the therapist says aloud and the scribe writes down — it never appears in an exercise name (0 hits in the 2,701-name catalogue vs. the details being the only place it can land). `details` is optional: a one-argument call behaves exactly as the engine always did, which is what keeps the change safe. Every call site passes it — Fix Procedures (`resolveItem`), Fix Private Pay (carried on `listDone()` rows), and the read-only preview.
- **`Fixer.readDetails(li)` vs `Fixer.currentDetailsText(li)`.** The reader that FEEDS the matcher deliberately matches `[aria-label="Intervention details"]` without requiring `contenteditable`, so a signed/locked note still resolves correctly. The diffing/writing helper keeps the stricter `[contenteditable="true"]` selector — it needs an editable node. Don't collapse the two.
- **Simulated activity is rule 0 and beats EVERYTHING, excludes included** (therapist's explicit ruling, 2026-09-22). A TKE, a bridge or a curtsey-step whose details document a simulation is moved to 97530 rather than left alone. Precedence here is positional, and a test asserts it stays at index 0. It is move-only on purpose: the detail sentence is its own justification, there is no approved canonical wording, and this also stops the item inheriting the losing rule's boilerplate. Note this ruling does NOT automatically extend to the pending cue rule — 97112 pays less than the 97530 rules it would outrank, so "higher-paying wins" argues the opposite there.
- **Justifications are append-only** (join existing + canonical with a single `\n`; never overwrite). MET/Rib used to "replace" — retired per therapists. Idempotent via an `includes()` dedup check.
- **Intersecting procedures:** justification follows the winning category. Concretely, "anterior step → single-leg balance" files under 97530 (step wins) and carries the step justification, not move-only.
- **Survey scoring — two families:** disability scales (DHI, Modified Oswestry, NDI, QuickDASH) are higher = worse ("% disability/handicap"); function scales (LEFS, KOS-ADLS) are higher = better ("% of full function"). **KOS target lookup converts the displayed % to raw /70 (×0.7)** then displays back as % (Ben's call; matches the 10-pt min-change).
- **Display formats follow the APP, not the delivered mapping's notes** (the mapping was a week stale): DHI stays "DHI score of X/100" (not "total score"); Modified Oswestry stays "% disability" only. Only the target *values* come from the mapping.
- **Feature toggles:** in-page settings panel + `localStorage` (rejected: Tampermonkey menu + extension popup — the MAIN-world `chrome.storage` gap makes the extension side costly and divergent; rejected: remote config — would break the no-data/no-network privacy claim). Settings button is decoupled from features (anchored to native controls) so it's reachable even if a feature breaks.
- **Local auto-update:** a git-ignored `*.local.user.js` build carries a `file://` `@updateURL`, so Ben pulls updates via Tampermonkey "Check for userscript updates" — no GitHub push. `npm run build:local` regenerates it.
- **Push policy:** commit locally; **Ben pushes** unless he asks otherwise in that turn. (Credentials do now work — see AGENTS.md. The old "no GitHub creds" note is obsolete as of 2026-10-13.)
- **2026-10-13 PHI incident — the reason the capture-filename rule exists.** Four real patient names were in this public repo: code comments and docs citing capture filenames, a test header saying its values were "the real ones parsed from the \<name\> initial-eval", and one commit message. Four of the eight occurrences had already been public for some time, including one shipped inside the published `content.js`. Fix: all 68 commits rewritten with `git filter-branch` (`--tree-filter` sed + `--msg-filter`) substituting `[patient]`, force-pushed with `--force-with-lease`, local `refs/original` dropped and gc'd — 0 of 68 reachable commits contain a name, and the tree at HEAD was unchanged by the rewrite. **A history rewrite does not purge GitHub**: old commits stay reachable by SHA until GitHub Support runs GC. Don't re-solve this; just never reintroduce it.
- **Web Store:** unlisted → IT force-install by ID; no permissions declared; `localStorage` needs no permission and isn't user-data collection, so the "no data" disclosures hold. Item ID `lnacagncbpglinobghcdeadaodonpjdf`.
- **Calendar auto Day→Week is SHELVED** (misbehaves). Code + `__athelasCalendarWeek()` hook remain; not called from the tick.
- **Two classes of billing error, and they're treated differently.** The 97110/97112/97530 shuffle is *wrong but paid*; a non-reimbursed code (98960) or a sequela diagnosis (7th character S) on a follow-up is *$0*. The second class gets: an override of the "leave alone" rules (staying put is never acceptable), and a warning button above the signature block. The first class does not.
- **Non-reimbursed codes are a CARD-level rule, not a name rule.** Every other rule keys on the intervention's name; `resolveNonReimbursed(name, cardCode)` keys on the CPT card the item is sitting in. Precedence: the name rule picks the destination when it has one (a squat under 98960 → 97530), else the family default (→ 97535). Not role-aware yet — if OT/SLP need different targets this becomes a per-discipline map.
- **Fix Diagnosis order is add → verify → remove**, never remove-first. A failed add followed by a remove would leave the note with no diagnosis at all. If the corrected code can't be found in the listbox, the original stays and the row is reported skipped.
- **Never click the diagnosis field's "Clear" X.** `button[aria-label="Clear"]` in the autocomplete's end-adornment removes EVERY diagnosis code. Deletion always goes through the individual chip's `svg[data-testid="CloseIcon"]`. (Hiding that X is a possible future feature.)
- **New diagnosis codes are appended to the END of the list.** If the code being replaced was the Principal (first) one, the replacement does not inherit that position — the review dialog says so, and points at the section's "Show reorder list". We do not automate the reorder.
- **Button status colours cost no polling.** Red = clicking would change something, green = clean, grey = busy. One shared `athStatusBus` (a single MutationObserver + trailing debounce with a max-wait cap) drives every subscriber; it skips hidden tabs and non-chart-note pages, each subscriber reads only its own section, and `athPaintButton` no-ops when the state hasn't changed. Explicitly rejected: a `setInterval` scan — these run on low-end clinic laptops.
- **The non-reimbursed warning counts only "Done" items.** Those are what actually bill, and they're exactly what Fix Procedures will move — so the warning always clears after the fix instead of sticking on an emptied card. An empty 98960 card left on the note is a manual removal.
- **There is no "first load" signal in the app — we keep our own.** Only the four free-text sections (Eval Subjective / Objective / Assessment / Plan) carry a `Last updated: …` chip and a `[aria-label="View change history"]` control; `plan_of_care`, `goals`, `diagnosis_codes` and `flowsheet` have none, there is no dirty/draft flag, and the SPA ships no inline state blob to read. So the plan-of-care auto-default records the note's own `chartNoteKey()` (patientId/appointmentId) in `localStorage['athelas-helper:poc-seen']` (capped at 400 keys, FIFO). That means "first time **this browser** opened this note with the helper", not "first time ever" — the honest limit. Four guards make it acceptable: the note's one shot is burned **even when we change nothing** (so a deliberately shortened plan is never revisited), it only ever lengthens and no-ops at/past target, evaluations only and never a signed note, and the toast carries a real **Undo**. `__athelasPocSeen()` / `__athelasPocForget()` / `__athelasPocForgetAll()` inspect and reset it. Rejected: reading the per-section "View change history" dialog (wrong sections, and opening a modal to decide whether to act is far too invasive).
- **Fix Plan of Care asks first, and only lengthens.** (The button does; the once-per-note auto-default above skips the dialog and offers Undo instead — that is the exception, and it exists because the clinic asked for a default rather than a button.) The clinic's wording was "auto default to 90 days", but this edits a certification document on every eval — specifically the plan the therapist just discussed with the patient ("that is what they told the patient they were going to start with"). So it's a red/green button with a before/after dialog, like every other fixer, not a silent default. It never shortens a longer plan, never touches frequency (the complaint is duration), and never drives the units Select (a MUI Select we can't verify offline — see the mousedown gotcha).
- **12 weeks, not 90 days — confirmed by the clinic (2026-09-06).** They asked for "90 days", but 90 days is 12.86 weeks: 12 weeks (84d) is the longest whole number of weeks inside a 90-day certification, and 13 (91d) would overshoot it. They accepted 12 weeks, so this is settled and we do NOT need to know whether the Duration-Units Select offers "Days". The target stays a per-unit map (`DAYS: 90, WEEKS: 12, MONTHS: 3`) so a form set to days or months still gets a sane value; `window.__athelasDurationUnitOptions()` survives as a diagnostic only.
- **The app owns the derived POC fields.** After setting `duration` we wait and check whether `end_date` / `visit_count` moved on their own, and only write them if they didn't — the app's own arithmetic beats ours (one captured eval was a day off our projection). If a write fails the toast names the field for manual fixing rather than pretending it worked.
- **Provider discipline (PT/OT/SLP) is readable but nothing is gated on it.** `athProviderInfo()` reads the credential next to the provider name in the notarize block; `athDiscipline()` returns null for unrecognized credentials rather than guessing, because the eventual use (a discipline-specific CPT map) must not act on a bad guess.
- **"Which provider is the logged-in user" = whoever owns the Sign button.** You can only sign as yourself; everyone else on the note shows "Awaiting Signature". Once signed, the same control is the disabled "Signed" button. **Do NOT use the "Supervising Provider" label** — across the captures the logged-in therapist is herself labelled Supervising Provider on some notes and still owns the Sign button. A co-signed note has no unique signer, so the discipline is cached in `localStorage['athelas-helper:me']` (credential + discipline only — no name — local, never transmitted) and used as the fallback.
- **Icon text pollutes `textContent`.** The app's material-symbol spans render their icon NAME as text: the Sign button's raw `textContent` is `"signatureSign"`. Match control labels with `athLabelText()` (skips `[data-testid="material-symbol"]`, `[data-icon]`, `[aria-hidden="true"]`, `i`/`img`/`svg`), never raw `textContent`. Also note "Awaiting Signature" *contains* "Sign", so these matches must be exact, not substring.

## Solved problems — don't re-solve these

- **Right-aligning an injected element ("move it to the right side").** THE recurring trap. The Functional-Outcomes section and each survey region are flex COLUMNS with `align-items: flex-start`, so a child does NOT stretch full-width and `justify-content: flex-end` has no effect. Use **`align-self: flex-end`** on the child. (Bit us on the survey quick-add panel AND the survey status button.) When the anchor lives inside a responsive-hidden wrapper (calendar "Clear All" is in a `tr-hidden lg:tr-block` div), insert BEFORE that wrapper so it stays visible at small widths.
- **MUI Select opens on `mousedown`, not `click`.** The calendar view (Day/Week/Month) select never opened its listbox from a native `.click()`. Dispatch `pointerdown` + `mousedown`, then click `[role="option"][data-value="week"]`.
- **`simulateClick` was double-firing.** It used to call native `.click()` AND dispatch a synthetic MouseEvent = two activations → "everything happened twice" (survey added twice, goal states added twice). Now: ONE activation (native; synthetic only if native is unavailable/throws).
- **Goal form add-chips.** The Create-Goal form has FOUR chips: Initial State, Current State, Target State, Status. Match a chip by its own exact text — matching a shared container returned the first (Current State) instead of Target State.
- **POC end date.** It's a sibling `<span>` after the "Plan of Care End Date:" label, not one text node. Read the label's following sibling. `#_r_f4_` is a dynamic React id — do not anchor on it.
- **Plan-of-Care form fields** (`[data-section="plan_of_care"]`, inside a `<form>`; all stable `name=` hooks): `input[name="duration"]` (number) + `[aria-label="Duration Units"]` (MUI Select, displays "Weeks", hidden native input `value="WEEKS"`), `input[name="frequency"]` + `[aria-label="Frequency Units"]` ("Per Week"), `input[name="start_date"]` / `input[name="end_date"]` (both `placeholder="MM/DD/YYYY"`, each with its own `button[title="Clear"]`), `input[name="visit_count"]`. Across the captured evals `visit_count == frequency × duration` and `end_date ≈ start_date + duration` (6wk: exactly +42 days; 12wk: +83, one short of 84) — so both look derived, but whether they RE-derive when duration is set programmatically is unverified. The Duration-Units options are not in the DOM until the Select is opened (MUI, and it opens on `mousedown`), so it is **unknown offline whether "Days" is an option** — which decides whether a 90-day default is "90 Days" or "12 Weeks".
- **Multiple goals.** Each created goal is a card in `[data-section="goals"]` with its own editable `initial_value` / `current_value` / `end_goal_value` inputs (title and date are behind an "Edit goal title and target date" button, so cards no longer carry a `name` field). Target the EMPTY Goal-Title field and scope all fills to the open dialog so you never overwrite an existing goal; match the "open" button by `create|add|new goal` (it currently reads "Add Goal").
- **Goal form: title is a textarea.** (15.25.2, from `captures/*_broken_goals.mhtml`.) A site update turned the Create-Goal dialog's Goal Title from `<input name="name">` into a MUI multiline `<textarea name="name">`. `input[name="name"]` then matched nothing: the script clicked "Add Goal", waited five seconds for a field that was already there, and gave up — the therapist saw an empty "Create new Goal" dialog. Look goal fields up by `name` on **either** tag (`goalFieldSel`). MUI's hidden auto-size twin `<textarea aria-hidden readonly>` has no `name`, so it never matches. `setReactValue` already picks the right prototype setter per tag. `tests/goal-form.test.js` guards this.
- **Goal form fills are dialog-scoped.** (15.25.2.) `createGoal` used to resolve fields as `form.querySelector(sel) || document.querySelector(sel)`. With existing goal cards on the note, the page-wide half resolves `initial_value` to the **first existing goal's** field, not the dialog's — so any miss inside the dialog (a slow chip, a renamed field) would have overwritten a real goal. The scope is now strictly the `[role="dialog"]` that owns the title, with no fallback, for fields, add-chips and the submit button alike. Don't reintroduce a fallback to make a failing lookup "work".
- **Goal form: verify, then submit.** (15.25.2.) `createGoal` re-reads every field it filled and clicks "Create Goal" only if all of them hold the requested value; otherwise it leaves the dialog open and the toast names the fields. It used to submit unconditionally, and an August test log shows it doing exactly that with a missing target state. Dates are compared as numbers so `1/5/2026` equals `01/05/2026`.
- **Toasts.** The returned API is `toast.done(ms)` (auto-close) — there is no `.arm()`. Toasts are click-to-dismiss with a 20s safety cap.
- **Calendar Open Note URL.** The chart-note link (`/ehr/v2/patients/{pid}/appointments/{aid}`) exists ONLY in the native hover popup — the patient id is NOT on the cell. Harvest + cache the href as the user hovers (they hover to reach the button anyway); open from the live anchor or cache. Synthetic hover did NOT reliably open the popup.
- **Off-screen appointment popup.** It's a MUI Tooltip positioned by an inline `transform` on `.MuiTooltip-popper` (stable hook: `[aria-label="Appointment Tooltip"]`). Read/adjust the translate to clamp it into the viewport (idempotent), and hide the `.MuiTooltip-arrow` on clamp — its hit area was blocking clicks.
- **Survey add input** is CSS-hidden until hover (`md:tr-invisible`) — force it visible; the autocomplete options are `[role="listbox"] [role="option"]`, matched by exact text.
- **Keyword-spam rejection.** Listing the survey acronyms (DHI, LEFS, …) in the store description triggered a Web Store "Keyword Spam" rejection. Describe surveys generically.
- **FS delete quirk.** The mount blocks `rm`/unlink (`mv` works). Use the delete-permission tool to delete; NEVER rename junk into `.git/refs/**` (once produced a bad ref that broke `git push`).

## Key DOM anchors (stable hooks)

- **App shell (changed Oct 2026 — the Quasar drawer is gone).** `.q-layout` now wraps a flex row `[data-slot="app-shell"]`: `aside[data-slot="app-shell-sidebar"]` (holding `[data-slot="resizable-panel"][data-side="left"]` with `data-state="expanded|collapsed"`, an inline `--panel-width: 220px`, and a `button[aria-label="Toggle Panel"]` drag rail) beside a column containing `nav[data-slot="app-shell-header"]` and `main[data-slot="app-shell-main"]`. `.q-page-container` still exists but sits *inside* `main` and no longer carries an inline `padding-left`. There is no `aside.q-drawer` or `.q-drawer-container` any more. The new shell's classes are `ds:`-prefixed (a new design system); the note itself is still `tr-` utilities + MUI, and none of our `tr-`/MUI rules reach into the sidebar (0 of its 141 elements move with the compact CSS on).
- Note scroller (the element whose 16px side gutters the compact CSS trims): `.tr-mx-4.tr-h-full.tr-overflow-x-auto`. It lost `tr-w-full` in Oct 2026 and gained `tr-min-w-0 tr-flex-1`, so don't key on the width class. The section sub-nav rail is still `.tr-w-[160px].tr-min-w-[160px].tr-max-w-[160px]` (200px at `md:`).
- Chart-note sections: `[data-section="functional_outcomes" | "goals" | "plan_of_care" | "flowsheet"]`; survey regions `[data-section="<survey display name>"]` (`id="collapsable-note"`, flex col); per-survey scores `[aria-label="Scores for <survey>"]` (exists only once scored).
- Survey region header: a `tr-items-center` row with `<button aria-expanded>` (ArrowDropDownIcon collapse toggle) + `<span role="heading">` (name); scores are a sibling wrapper.
- Note type: `input[aria-label="Clinical Note Type"]` value (e.g. "Initial Evaluation") → gates initial-eval features.
- Diagnosis codes (`captures/*_diagnotis_codes_example.mhtml`): section `[data-section="diagnosis_codes"]`, header row is the same `tr-grid tr-grid-cols-[1fr_auto]` shape as the flowsheet's (so a right-aligned button lands the same way). Search box `input[aria-label="Search for diagnosis codes"]`; results are portaled to `<body>` as `li[role="option"][title="<code>"]` (exact hook — no text parsing needed; each also holds `input[type=checkbox][value="<code>"]`). **`button[aria-label="Clear"]` in the end-adornment wipes every code — never click it.** Also present: `button[aria-label="Show reorder list"]`.
- Signature / notarize block: `[data-section="notarize"]`, containing `section[aria-label="Provider(s)"]`. Each provider's name cell is a `<div>` of `<span>`s — `[name, credential]`, plus a third `"Supervising Provider"` span on supervisors; its parent row also holds that provider's sign state — an enabled `Sign` button (= the logged-in user), a disabled `Signed` button (= the logged-in user, note already signed), or an `Awaiting Signature` label (= someone else). Watch out for two traps: the section's own heading is the same 2-span shape (icon + "Provider(s)") but lives inside a `<label>`, and control text is polluted by icon names (see above). The credential (`DPT`, `PT`, `OTR/L`, …) is the ONLY place the page states a discipline — not in the app shell, nav, user menu, or any inline JSON; the SPA fetches everything, so the alternatives are an API call or the `/my_account` route.

Local files don't run scripts in the preview pane — serve the folder (`python -m http.server`) and open it over http. Re-extract the functions from the userscript before trusting a re-run.
- Goal form (a MUI `[role="dialog"]` headed "Create new Goal", portaled to `<body>`; fill via `setReactValue`): `name="name"` (title — a `<textarea>` since Oct 2026, an `<input>` before), `name="due_date"` (`<input>`, segmented MM/DD/YYYY, type digits "MMDDYYYY"), then after their add-chips are clicked `name="initial_value"` and `name="end_goal_value"`. ## Survey scoring quick reference

Lookup metrics: QuickDASH = displayed % (lower better); LEFS = raw /80 (higher better); Oswestry & NDI = raw /50 (lower better); DHI = total score /100 (lower better); KOS-ADLS = displayed % → raw /70 ×0.7 (higher better). Target tables + full descriptions are in `reference/reference_surveys.txt`; the engine is `surveys/survey-scoring.js` (tested).
